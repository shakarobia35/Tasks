# 构建工具

当我们习惯了在node中编写代码的方式后,在回到前端编写html、css、js这些东西会感觉到各种的不便。比如:不能 放心的使用**模块化规范(浏览器兼容性问题)**、即使可以使用模块化规范也会面临**模块过多时的加载问题**。

我们就迫切的希望有一款工具可以对代码进行打包,将多个模块打包成一个文件。这样一来即解决了兼容性问题,又 解决了模块过多的问题。 

构建工具就起到这样一个作用,通过构建工具可以将使用ESM规范编写的代码转换为旧的JS语法

## 自动化构建

### npm script

Node.js 自带的脚本执行功能，在 package.json 的 scripts 字段中定义命令行任务。
它可直接调用 node_modules/.bin 下的可执行文件，无需额外安装构建工具。适用于简单的项目启动、测试、lint 检查；常作为 Gulp 或 Webpack 的启动入口（如 "build": "webpack"）。

### gulp

基于流（Stream）的自动化任务运行器，采用代码优于配置的方式。
它通过 .pipe() 串联处理文件（如 Sass -> CSS -> 压缩），任务可并行或串行执行。适用于纯粹的构建工作流（如压缩图片、编译 Less、文件合并），不关心模块化逻辑。

### 区别

|          | NPM                                                        | Scripts Gulp                                               |
| -------- | ---------------------------------------------------------- | ---------------------------------------------------------- |
| 实现方式 | 直接在 scripts 中写 CLI 命令                               | 编写 JavaScript 任务代码（gulpfile.js）                    |
| 复杂度   | 适合简单、线性的命令                                       | 适合复杂、多步骤的流程控制（串/并行）                      |
| 中间结果 | 通过临时文件传递（写入磁盘再读取）                         | 通过内存流传递（不落盘，速度更快）                         |
| 当前趋势 | 现代工具（Vite/Webpack）均优先支持 CLI，NPM Scripts 更通用 | 大型历史项目常用，但新项目正逐渐被集成度更高的打包工具替代 |



## 模块化打包

### Webpack

是现代前端开发中最重要的模块打包器之一，它将项目中的所有资源都视为模块，通过依赖图进行静态分析和打包。

- **输入输出灵活**：支持单文件和多文件输入输出，可以进行复杂的模块化输出，并且支持全目录结构。
- **文件捆绑和格式支持**：具有强大的捆绑功能，并支持 ESM、CJS、UMD 等模块格式输出。
- **CSS 和资源处理**：具备强大的 CSS 预编译和资源处理能力，并支持插件扩展以进行图片、字体等文件处理。
- **Polyfill 支持**：通过插件或配置，支持 Polyfill 和按需 Polyfill，非常适合构建复杂的应用程序。

### Rollup

**面向库和组件**：Rollup 更适合打包 JavaScript 库和组件库，支持单多文件输入、输出，并具有原目录输出功能。

**多种模块格式**：支持 ESM、CJS、UMD 等多种模块输出，适合发布为第三方库供其他项目引用。

**按需资源处理**：图片和 CSS 处理需要借助插件完成，适合需求不复杂的场景。

**Polyfill 支持**：通过插件实现 Polyfill 和按需 Polyfill，适合多环境兼容需求。

**ts编译**:@rollup/plugin-typescript、rollup-plugin-swc(不支持生成.d.ts)、rollup-plugin-typescript2+*ttypescript(停止更新)*

### Parcel

Parcel 是一个快速、零配置的前端打包工具，支持自动化地打包JavaScript、CSS、HTML等资源，并具有快速的构建速度和友好的开发体验。

### Snowpack

Snowpack 是一个面向现代前端开发的构建工具，它利用浏览器的原生ES模块加载能力，实现快速的开发构建过程。

### 区别

|              | Webpack              | Rollup        | Parcel            | Snowpack                           |
| ------------ | -------------------- | ------------- | ----------------- | ---------------------------------- |
| 配置成本     | 高（需要写大量配置） | 中            | 极低（零配置）    | 低                                 |
| 打包方式     | 全量打包             | 全量打包      | 全量打包          | 开发时未打包，生产时打包           |
| 模块规范     | 支持所有规范         | 专注 ESM      | 支持所有规范      | 利用浏览器原生 ESM                 |
| Tree Shaking | 支持（需配置）       | 原生支持      | 支持              | 支持                               |
| 适用定位     | 大型应用             | 三方库/组件库 | 快速原型/小型项目 | 探索现代 ESM 开发（历史/备用方案） |

### 构建工具在项目里主要解决了哪些问题？

· 语法转换：将浏览器不支持的现代语法（ES6+、TypeScript、JSX）转换为兼容的 ES5 代码。
· 模块化支持：将 Node.js 环境下的 CommonJS 或 ESM 模块规范，打包为浏览器可识别的依赖关系。
· 资源处理：处理非 JS 资源（CSS、图片、字体），使其能被 JS 引入或独立输出。
· 开发效率优化：提供热更新（HMR）、开发服务器、代码压缩和环境变量注入。

**若不使用，可能会遇到**：

· 无法使用 import 语法（浏览器兼容性差），只能通过 <script> 手动加载多个文件，导致全局变量污染和加载顺序混乱。
· 无法处理 CSS/图片：需手动在 HTML 中 link 样式，无法实现样式的模块化隔离。
· 需要手动压缩混淆：上线前需借助外部工具手动处理，流程繁琐且易出错。
· 无热更新：每次修改代码需手动刷新浏览器，开发效率极低。
· 难以引入 npm 包：必须通过 CDN 链接，无法享受 npm 生态的版本管理优势。

### Webpack 和 Rollup 的侧重点有什么不同？

1. 定位与职责不同

· Webpack：它的核心目标是打包一个完整的应用程序。所以它必须处理项目里所有类型的文件——图片、字体、CSS、甚至 HTML，都要能管起来。
· Rollup：它的核心目标是打包一段纯粹的 JavaScript 代码。它不关心图片怎么引，只关心 JS 代码本身怎么组织和输出。

2. 产出物要求不同

· Webpack：为了支撑应用运行，打包后的文件会自带一套复杂的模块加载逻辑（运行时），导致体积偏大，但对应用来说这无所谓。
· Rollup：库发布到 npm 上，体积越小越好。Rollup 打包出的代码干净、无额外胶水代码，且对 ES Module 的静态分析最彻底，Tree Shaking 效果最好。



如果要写一个网站/管理系统，用 Webpack（或现在的 Vite）。
如果要写一个工具库/组件库发到 npm，用 Rollup。



· 选 Webpack：大型应用项目（SPA、多页应用）。需要处理大量图片、字体、CSS 资源，且需要按需加载（Code Splitting）、热更新等复杂功能。
· 选 Rollup：封装第三方库/工具库（如 UI 组件库、utils 函数库）。因为库的体积必须尽量小，且用户不会希望引入额外的 Webpack 运行时，Rollup 打包出的纯 ESM 格式最干净。

### “打包后体积变⼤/变⼩”通常与哪些因素有关？

导致体积变大的因素：

· 构建工具自身的运行时注入：Webpack 会在打包产物中注入自己的模块管理代码（约几百行），相比原始源码会增加体积。
· Polyfill 垫片：为了兼容低版本浏览器，引入了 core-js 或 babel/polyfill，这会显著增加体积（如 async/await 的转换）。
· Source Map：开启 devtool 生成 source-map 文件时，体积会暴涨（但仅用于调试，线上需关闭）。
· Base64 内联资源：将小图片转为 Base64 直接嵌入 JS，会增加文本体积（通常 4/3 倍膨胀）。

导致体积变小的因素：

· 代码压缩：使用 Terser 或 ESBuild 移除空格、缩短变量名（通常能减少 30%-50%）。
· Tree Shaking（摇树）：移除项目中未使用的函数或模块（ESM 静态分析才能有效剔除）。
· Scope Hoisting（作用域提升）：Rollup 原生支持，Webpack 需配置 ModuleConcatenationPlugin，将多个模块合并到一个函数作用域中，减少闭包代码，从而缩小体积。
· Code Splitting（代码分割）：将第三方依赖（如 React、Vue）单独抽离为 vendors.js，利用浏览器缓存避免重复加载，虽然总体积未变，但首屏加载体积变小了。
