# 计算机与Web基础

## 计算机基础

### TCP / IP 初识

***TCP/IP 是供已连接因特网的计算机进行通信的通信协议。这就像你去商店购物所使用的交通方式，比如汽车或自行车。***

> TCP (传输控制协议) - 应用程序之间通信
>
> IP (网际协议)  - 计算机之间的通信

TCP 负责应用软件（比如您的浏览器）和网络软件之间的通信。

IP 负责计算机之间的通信。

TCP 负责将数据分割并装入 IP 包，然后在它们到达的时候重新组合它们。

IP 负责将包发送至接受者。

TCP/IP 协议族里重要的一点就是分层。TCP/IP 协议族按层次分别分
为以下 4 层：应用层、传输层、网络层和数据链路层。

> 1. 应用层（FTP、DNS）：负责提供具体的服务内容。。HTTP协议也处于该层。
> 2. 传输层（TCP、UDP）：负责处于网络连接中的两台计算机之间的通信（谁发的？发给谁？）。
> 3. 网络层（IP）：负责处理在网络上流动的数据包。数据包是网络传输的最小数据单位。规定了通过怎样的传输路线到达对方计
>    算机，并把数据包传送给对方。
> 4. 网络接口层（链路层）：负责物理硬件传输（网线、光纤、WiFi 信号）。

利用 TCP/IP 协议族进行网络通信时，会通过分层顺序与对方进行通
信。<span style="color:red">发送端从应用层往下走，接收端则向应用层往上走。</span>

发送端在层与层之间传输数据时，每经过一层时必定会被打上一个该
层所属的首部信息。反之，接收端在层与层传输数据时，每经过一层
时会把对应的首部消去。这种把数据信息包装起来的做法称为封装

#### TCP/IP寻址

TCP/IP 使用 32 个比特来编址。一个计算机字节是 8 比特。所以 TCP/IP 使用了 4 个字节。

IPv6——新的IP协议，由8个16位无符号整数，每个整数用 4 个十六进制位表示。数之间用：分开。冒号十六进制记法允许一串连续的0用：取代。为了保证零压缩有清晰解释，任一地址中只能用一次零压缩。

#### TCP 报文结构

TCP 位于传输层，能提供可靠的<u>字节流服务</u>(将大块数据分割成报文段为单位的数据包来管理）。

``` text
[   IP头部（20字节）  ][     TCP头部（20字节）    ][ 数据（2字节） ]
                       \_________________________________/ 
                     “TCP 报文” [TCP 头部（固定20字节）+ 数据(Hi)]
```



| 字段                          | 作用                                                         |
| ----------------------------- | ------------------------------------------------------------ |
| 源端口 / 目标端口 2           | 告诉数据从哪个程序来，到哪个程序去                           |
| 序列号（Seq） 4               | 给当前数据包编号，保证接收端能按顺序拼接。                   |
| 确认号（Ack） 4               | 告诉发送端“我已收到第 X 号包，请发下一个”。                  |
| 标志位（URG/ACK/SYN/FIN） 0.5 | 握手和挥手的关键开关。握手靠 SYN=1，挥手靠 FIN=1，确认靠 ACK=1。 |
| 窗口大小 2                    | 告诉对方“我还能收多少数据”，用于流量控制。                   |

#### 各协议在通信过程中的作用

> HTTP协议职责：生成针对目标Web服务器的HTTP请求报文
>
> TCP 协议职责：为方便通信和更易传送大数据，把数据分割成报文段。它能确认数据最终是否送到对方。
>
> IP协议职责：搜索对方地址，边中转边传送
>
> TCP协议职责：从对方处接收报文段，按序号以原来的顺序重组请求报文。
>
> HTTP协议职责：对Web服务器请求的内容做处理

#### TCP 建立连接与释放连接的过程

##### 三次握手（建立）

① 客户端 -> 服务器：SYN=1（发送申请，给出客户端序列号 x）。

② 服务器 -> 客户端：SYN=1, ACK=1（接收申请，给出服务器序列号 y，确认收到x+1）。 

③ 客户端 -> 服务器：ACK=1（收到服务器的 y+1，连接建立，开始发数据）。 

前端视角：当看到 ERR_CONNECTION_TIMED_OUT，大概率是第一步的 SYN 包没人回应（服务器关机或防火墙拦截）。 

##### 四次释放（断开） 

① 客户端 -> 服务器：FIN=1（数据发送完毕，想挂断）。 

② 服务器 -> 客户端：ACK=1（收到请求，检查是否有剩余数据要发，先不挂）。

③ 服务器（发完后） -> 客户端：FIN=1（检查完毕，可以挂断）。 

④ 客户端 -> 服务器：ACK=1（收到，正式断开）。 

释放比建立多一次是因为建立时两边都默认准备好；而释放时，服务器可能还在传文件，要等它把“剩余快递”派送完再主动要求挂断。

### HTTP 初识

***超文本传输协议是一个定义客户端和服务器之间如何交流的应用层协议。***

在两台计算机之间使用 HTTP 协议通信时，在一条通信线路上必定有一端是客户端，另一端是服务器端。请求从客户端发出，最后服务器端响应该请求并返回，即在没有收到请求前不会发送响应。

#### 报文结构

***起始行 + 头部（Header）+ 空行 + 主体（Body）***

请求报文（Request）：

```http
POST /api/todo HTTP/1.1            // 请求行（方法 + 路径 + 版本）
Host: www.example.com             // 请求头（Host、User-Agent等）
Content-Type: application/json
                                        // 空行（必须存在）
{"title": "学习TCP/IP"}                // 请求体（POST/PUT的数据）
```

响应报文（Response）：

```http
HTTP/1.1 200 OK                        // 状态行（版本 + 状态码 + 状态描述）
Content-Type: application/json          // 响应头
Content-Length: 28
                                        // 空行
{"code": 0, "data": "success"}         // 响应体
```

前端视角：在浏览器 F12 -> Network 里看到的 Headers 标签页，就是把上面这些内容整理后的可视化界面。

#### 状态码含义

| 分类            | 代表性码                                                     | 含义（前端处理方式）                               |
| --------------- | ------------------------------------------------------------ | -------------------------------------------------- |
| 1xx（信息）     | 101                                                          | 切换协议（WebSocket 握手时出现）                   |
| 2xx(成功)       | 200(OK)、201(Created)                                        | 请求成功，正常解析数据即可                         |
| 3xx(重定向)     | 301（永久）、302（临时）、304（缓存）                        | 浏览器会自动跳转；304 表示用本地缓存，不发数据     |
| 4xx(客户端错误) | 400（参数错误）、401（未登录）、403（无权限）、404（找不到） | 检查传参、检查 Token、检查 URL 路径                |
| 5xx(服务端错误) | 500（内部错误）、502（网关错误）、503（过载）                | 问题出自后端服务器，前端可展示友好提示，并上报监控 |

#### 完整的 HTTP 请求 / 响应流程

在浏览器地址栏输入 `www.example.com`并回车，背后发生了这一切：

1. DNS 解析：浏览器向 DNS 服务器问“这串域名对应的 IP 地址是多少？”
2. 封装与寻址：应用层生成 HTTP 请求报文 -> 传输层加上 TCP 头部 -> 网络层加上 IP 头部 -> 链路层通过网卡发出。
3. TCP 三次握手：找到 IP 对应的服务器，建立可靠连接（SYN -> SYN-ACK -> ACK）。
4. 发送 HTTP 请求：客户端把封装好的 HTTP 报文通过 TCP 连接发给服务器。
5. 服务器处理：服务器解析 HTTP 报文，执行业务逻辑（查数据库等），生成 HTTP 响应报文。
6. 返回与渲染：服务器把响应报文通过 TCP 传回浏览器，浏览器解析 HTML/CSS/JS，渲染成你看到的页面。
7. TCP 四次挥手：数据传输完毕，关闭连接（或 Keep-Alive 复用连接）。

## Web基础

### 互联网

> 网络交换机确保从一台计算机上发出的消息仅可以到达目标计算机
>
> 路由器负责在不同网络之间转发消息。当数据包到达时，它会读取收件人的地址，直接将数据包转发给正确的收件人，无需经过层层中转。
>
> 调制解调器能将网络中的消息转换为电话基础设施可处理的形式，反之亦然。
>
> ISP 是管理特殊路由器的公司。这些路由器相互连接，并能访问其他 ISP 的路由器。来自网络的消息通过 ISP 网络的网络传输至目标网络。

##### 浏览器解析文件顺序

浏览器首先解析 HTML 文件，识别所有指向外部 CSS 样式表的 `<link>` 和指向脚本的 `<script>` 元素引用。

继续解析 HTML 文件的同时，浏览器继续向服务器发送请求以获取 `<link>` 元素中找到的 CSS 文件以及 `<script>` 元素中找到的 JavaScript 文件，然后解析 CSS 和 JavaScript。

接着浏览器会给解析后的 HTML 文件生成一个DOM树（在内存中），会给解析后的 CSS 文件生成一个CSSOM 树（在内存中），并且会编译和执行解析后的 JavaScript 脚本文件。

伴随着构建 DOM 树、应用 CSSOM 树的样式，以及执行 JavaScript 脚本文件，浏览器会在屏幕上绘制出网页的界面；用户看到网页界面也就可以跟网页进行交互了。

#### DNS

DNS系统能使用特殊的服务器将输入到浏览器（如“mozilla.org”）的网址匹配到网站真实的（IP）地址。

工作流程：输入网址后，若本地DNS缓存过此域名，则可直接确定IP地址，若否，则询问DNS服务器，告诉电脑已注册的域名所匹配的IP。知道IP后，浏览器即可与Web服务器协商内容。
